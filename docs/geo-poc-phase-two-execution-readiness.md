## 최소 파일럿 제안과 실제 전송 범위

**현재 확정된 전송 자료 ID: 없음.** 아래 6개는 권한 확보를 우선 검토할 후보이며 전송 승인 목록이 아니다. 내용은 기존 발췌의 지정 구간 전체로 한정하고, 원문 전체를 추가하지 않는다.

| 조건부 후보 | 전송을 검토할 구간 | 필요한 근거·비식별 확인 | 역할 — 평가자용, 모델에는 제공하지 않음 |

모든 후보의 권한·비식별 최종 상태는 현재 미확정이다. S06 회차 등 추가 가림이 필요하면 원본을 덮어쓰지 않고 **별도 파생본·가림 이유·새 해시·원문 위치 대응표**를 검토한 뒤 최종 범위를 다시 제출한다. 무관한 개인정보만 가리고 소비자 의미를 새로 쓰지 않는다. 근거가 없으면 해당 행은 제외하거나 사용자 제공 실제 자료로 대체한다.

최소 파일럿은 이와 같은 서로 다른 원문 성격을 포함하는 **실제 자료 4~6개, 같은 묶음 3회**로 제안한다. 검증 항목을 함께 살피기에는 6개를 권고하되 개수를 채우기 위해 허구·중복·유도된 답변을 넣지 않는다. 단일 자료 유형만 남으면 검증 가능한 항목을 줄여 보고하며, 발견 순위나 시장 대표성은 보류한다.

모델에 전달할 필드는 기존 앱 계약에 맞춰 market/language와 행별 익명 row UUID, 승인된 발췌 text, channel 도메인, publishedAt(미상은 null)이다. source URL·작성자명·사진·IP·주문번호·동의 증적·위 예비 해석 표·기존 질문·공식 제품 정보는 전달하지 않는다. 출처 URL·권리 증적은 내부 감사 기록에 둔다. 도메인·날짜도 제공 범위에 포함해 승인받는다. URL을 빼도 정확 문구 재검색 위험은 남는다.

### 기존 자료 권한 확보가 어려운 경우 — 권고 대안

기존 21개는 내부 검토 대상으로 보존하고 **사용자가 적법한 처리·외부 제공 근거를 확인할 수 있는 기존 실제 소비자 원자료 4~6개**로 파일럿을 시작한다. 예: 적법하게 보유한 상담·인터뷰·설문 자유응답 원문 중 제공 목적·처리 서비스 범위가 맞는 자료. 고객 명단·전체 상담기록을 보내지 말고 최소 발언 구간과 권한 확인 정보를 별도로 준비한다.

권한 확인 정보는 실제 관리자가 점검한다: 자료 ID/원본 위치, 권리자·정보주체와 권한 관계, 적용 근거 또는 허락 증적의 내부 식별자·일자·범위, OpenAI 서비스 제공 목적·필드·보관/학습 설정과의 적합성, 제3자 언급 여부, 가림 이력, 철회·삭제 요청 처리. 동의서·계약서 원문과 신원을 모델 프롬프트나 공개 GitHub에 올리지 않는다. 동의만이 유일한 가능한 근거라고 단정하지 않되, 실제 적용 근거가 확인되지 않으면 전송하지 않는다.

새 자료는 U01~U06 같은 신규 ID로 연결하고 실제 존재하는 발언을 그대로 보존한다. 사용자가 니즈·정답 질문·불만을 작성해 넣거나, 필요한 유형을 맞추도록 답변을 유도하지 않는다. 권한 증적이 있어도 분석 표본의 대표성이 생기는 것은 아니다. 새 원문은 현재 미제공이므로 내용·해시·질문 후보를 미리 만들지 않았다.

## 승인 후 실행·보존 절차

1. 허용된 실제 행과 파생본, 출처 범위, 제공 필드, 계정 처리 설정, 실제 서비스·모델 표시명, 추론 설정을 확정한다. **정확한 ID·발췌 SHA-256·비식별 상태·권리 근거·모델을 한 표로 제출해 실행 승인을 받은 뒤** 전송한다. 현재는 전송 가능한 데이터가 없어 실행 승인 요청까지 준비된 상태가 아니다.
2. 기존 앱의 자료 연결·선택 행 권한 검토 기능을 사용한다. 같은 프로젝트와 같은 row UUID·원문 스냅샷을 고정하고 백업한다. 예비 검토 JSON은 앱 권한 승인 파일이 아니며 일괄 가져와 승인 상태로 쓰지 않는다.
3. 정순 기준의 selected row IDs를 먼저 기록한다. 역순은 이를 뒤집고, 해시 순서는 기존 `evidenceDigest(row UUID)`의 오름차순이다. 이 값은 SHA-256(canonicalJson(row UUID))이며 본문 해시 정렬이나 B/S 별칭 정렬로 바꾸지 않는다. 실제 순서·각 해시를 실행 manifest에 저장한다.
4. 기존 `prepareQuestionDiscovery`로 세 실행을 만든다. 규칙·자료·서비스·모델·설정은 같고 순서만 바꾼다. 실행별 runId·inputHash·promptHash는 별도 값으로 보존하며 같은 값이라고 가장하지 않는다. 실제 발췌와 메타데이터의 집합 해시를 별도 기록해 세 묶음의 구성 동일성을 대조한다.
5. 새 대화 3개에서 해당 요청문을 각 1회 전송한다. 앞선 대화 결과·감리표·정답·개발 대화를 붙이지 않는다. 동일한 평가자표를 모델에게 보여주지 않는다. 모델이 질문·추가 자료를 요구하면 임의 보충하지 않고 그 응답을 결과로 보존한다.
6. 사용자 입력과 모델 출력의 보이는 전체 원본을 각각 UTF-8 텍스트로 저장한다. 예: `forward.prompt.txt`, `forward.response.original.txt`, `reverse.*`, `hash_order.*`. 실행 시각·표시 모델·추론 설정·서비스 모드·기억/도구/데이터 설정 확인 수준을 `execution-manifest.json`에 기록한다. 모델 설정 증적 화면에는 계정 이름·메일을 가린다. API의 원시 응답·숨은 추론 기록을 확보한 것으로 표시하지 않는다.
7. 각 파일의 SHA-256과 앱 실행을 연결한다. 형식 오류·거절·중단·누락도 원본 시도로 저장하고 임의 수정하지 않는다. 수선본이나 재요청은 별도 파생본·새 시도로 표시한다. 원본 질문 발견 결과를 사람이 만든 JSON으로 대체하지 않는다.
8. 승인 범위 안에서만 분석 앱의 응답 가져오기·자동 대조·저장/재열기를 확인한다. 개인정보·권리 증적과 실제 비공개 소비자 응답을 공개 저장소에 커밋하지 않는다. 허용된 보관 장소와 공개 가능한 요약 범위는 실행 승인표에 함께 지정한다.

현재 실행 파일은 아직 없으며 `pilot-approval-proposal.json`은 조건부 후보·공란 모델 확인 정보를 가진 제안서다. 실제 요청문이나 모델 응답으로 오인하지 않는다.

| 만족·미충족 구분 | 만족·기대·장애·해결된 경험과 관심을 구분 | 만족을 불만이나 미충족 수요로 확정, 미사용 원인 창작 |

| 순서 변화 | 후보 union의 지지 행 집합과 의미를 사람이 대응시키고 군집 포함/분리·유형·누락·decisionImpact 변화 기록 | 첫 항목 자동 우선 선정, 상충 차이를 숨기거나 다수결로 정답 확정 |
| 표본의 우선순위 | 소표본·독립성 미상이므로 검토 우선순위는 보류. 배열 표시 순서와 구분 | 보류가 같다는 사실을 순위 정확도·대표 니즈 입증으로 보고 |
| 저장·재검증 | 입력/원본 응답/검토/실패 기록과 해시를 저장하고 재열기 대조 | 권한·원문·메타데이터 변경 후 기존 승인 유지 |

결과표는 **전 후보**의 인용·AI 해석·다른 해석·개발 AI 보조 판단·사용자 판단·최종 상태를 포함한다. 누락 장부는 **전 입력 행**을 포함하고 후보가 없는 행도 기록한다. 원자료에 질문이 없으면 질문을 만들지 않는 것도 정상이다. 모델에 제공하지 않은 원문 영역의 손실과 모델의 입력 내 누락을 구분한다. 표본 내 누락/오분류율을 계산하더라도 분모·불확실 사례를 공개하고 시장 전체 정확도로 환산하지 않는다.

인용 변조·근거 없는 의미 추가·가설의 사실화·만족의 미충족화가 있으면 해당 후보는 보류한다. 서비스/모델 미확인, 권한 불충족, 같은 입력 집합 실패, 기억·도구 오염은 실행 단위 유효성 보류다. 모든 실패를 남기고 첫 성공 응답만 고르지 않는다. 사용자 의미 검토와 감리 전에는 2단계 전체 완료로 판정하지 않는다.

## 이번 변경과 승인 요청

이번 변경은 권한 사전 검토표·실행 준비안·진행 기록뿐이며 앱 코드·권한 필드·원자료·기존 시험은 수정하지 않았다. 새 단위/UI 시험이나 실제 모델 품질 시험을 실행하지 않았다. 기존 f3166d0의 CI 결과를 이번 실모델 검증 결과로 전용하지 않는다. 계정 접근·모델 선택·전송·유료 호출은 하지 않았다.

회장님께 요청드릴 결정은 다음과 같다.

1. **권고 B안:** 적법한 외부 제공 근거가 확인되는 사용자 보유 실제 원자료 4~6개로 파일럿 준비를 진행할지, **A안:** 기존 조건부 후보 6개의 개별 이용 근거 확보를 우선할지 선택한다. 두 경우 모두 자료 권한 증적 없이 실행하지 않는다.
2. 서비스 제안 **ChatGPT 웹 Work 수동 실행**, 모델 후보 **GPT-6.1 Sol / Medium**를 계정에서 선택 가능한지 사용자 본인이 확인한다. 미공개 버전은 미상으로 기록한다. 다른 모델만 가능하면 표시명을 받아 준비안을 수정한다.
3. 이번에는 준비안과 자료 확보 경로를 승인받는다. 실제 데이터·모델·처리 조건이 확정되면 정확 전송표로 **실행 승인**을 요청한다. 지금 자료 21개나 후보 6개의 일괄 전송 승인을 요청하지 않는다.

승인을 요구하는 이유는 사용자의 이번 지시인 “실제 모델 분석을 실행하기 전에 위 조건을 보고하고 승인을 요청하십시오”이며, 스킬에 따른 추가 승인 절차가 아니다. PoC 3단계·작성/Word 변경·main 병합·운영 배포·유료 API 금지를 유지한다.
