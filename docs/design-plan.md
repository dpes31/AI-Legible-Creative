# 화면과 로직을 함께 다듬는 계획

작성: 2026-10-20 · 상태: 디자인 1차안. 검증 로직의 완료 보고가 아님.

## 회장님 요청의 해석

사용자가 하는 일은 적게, 앱이 확인하는 일은 깊게 만든다. 처음부터 조사 설정을 모두 묻지 않고, 분석 요약에서 필요한 근거만 열어 확인하게 한다. 결과는 실제 채널에 맞는 독립 문서로 제공한다. 모션은 다음 행동과 근거의 관계를 알려준다.

기본 방향은 **밝은 작업실, 넓은 여백, 큰 한국어 제목, 선명한 한 가지 강조색**이다. 색상이나 UI 라이브러리 결정을 회장님께 다시 요청하지 않고 테스트 브랜치에 적용한 뒤 실제 화면으로 검수받는다.

## 화면별 설계

| 화면 | 처음 보이는 내용 | 필요할 때 여는 내용 | 우선 행동 |
|---|---|---|---|
| 정보 입력 | 대상 이름과 구분, 우선 목적, 고객 상황/미정 | 모델·설명·공식 링크·선택 채널. 파일은 분석 화면에서 추가 | 브랜드 분석 시작 |
| 분석 확인, 조사 전 | 대상·목적 요약, 수동 조사 요청문 만들기 또는 가능한 자동 작업 | 자료 추가, 전달 허용 범위, 조사 요청문 | 조사 요청문 복사 / 자동 조사 시작 |
| 분석 확인, 조사 후 | 적합 고객, 선택 이유, 경쟁 차이, 남은 확인 사항, 채널별 메시지 | 주장별 원문·비교 조건·반대 근거·질문 구분 | 확인한 근거로 문구 만들기 |
| 결과 받기, 작성 전 | 선택 채널과 사용 가능한 근거 요약 | 작성 요청문, 자료 부족 설명 | 작성 요청문 복사 / 자동 작성 시작 |
| 결과 받기, 작성 후 | 한 채널의 본문, 사용 상태, 복사 | 근거, 작성 메모, 이전 버전, 재작성 제안, 파일 형식 | 본문 또는 검토용 초안 복사 |

상태에 따라 같은 화면 안의 중심 내용이 달라진다. 수동 요청문 패널이 완성된 문서 위를 계속 차지하지 않게 접는다. 조사·작성 화면을 추가 단계로 만들지 않는다.

### 1. 입력

- PC: 소개·산출물 안내 왼쪽, 실제 입력 오른쪽. 모바일: 짧은 소개 다음 입력, 산출물 안내는 아래.
- 대상 구분은 이름과 같은 묶음에 둔다. 고객 상황을 입력하면 ‘아직 정하지 않았어요’가 해제되며, 다시 미정으로 바꿔도 입력 문장은 보존한다.
- 공식 링크는 선택 사항. 같은 이름·다른 모델이 의심될 때만 구분 정보를 요구한다.
- 현재 수동/자동 선택은 유지하되 자동 미설정 이유를 바로 보여준다. 모드를 바꿔도 입력을 지우지 않는다.
- 기존 프로젝트는 이어서 하기와 새 작업 입력을 구별한다. 다른 대상으로 바꾸면 기존 자료를 보존한 새 프로젝트가 된다.

### 2. 분석

상단은 ‘이번 문구에서 강조할 내용’ 한 문장으로 시작한다. 분석 결과가 없으면 요약을 꾸며 채우지 않는다.

| 카드 | 실제 도메인 데이터 | 확인할 조건 |
|---|---|---|
| 이런 상황에 맞습니다 | audience + ConsumerQuestion.provenance | 확정 고객과 조사 가설을 구별 |
| 선택할 이유 | Recommendation + Claim | 근거 없는 추천은 보류 표시 |
| 경쟁 제품과의 차이 | Comparison | 공통 장점·조건부 차이·비교 미확인·실제 약점 구별 |
| 더 확인할 내용 | missingEvidence / conflicts / unreviewed | 실패와 자료 없음 구별, 최소 보완 항목 제시 |
| 채널에 담을 메시지 | 채널 계획 + 허용 주장 | 광고를 위해 조건을 지우지 않음 |

기존 도메인에 없는 중간 결과는 구조부터 추가하고 화면에 연결한다. 현재는 채널 계획 등 일부 중간 결과가 부족하다. 카드 디자인만 추가하고 전략 분석이 완성됐다고 표시하지 않는다.

PC는 2열, 핵심 요약을 본 뒤 근거 패널로 이동한다. 모바일은 한 열이며 해당 카드 바로 아래에 원문을 펼친다. 처음에는 접근성이 검증된 기본 details 패턴을 사용하고, 시트가 꼭 필요하면 닫기·초점 복귀·키보드 처리를 함께 구현한다.

### 3. 결과

- PC: 6채널 선택 영역, 넓은 문서 편집 영역, 선택 문장의 근거 패널.
- 모바일: 채널 선택 목록, 본문, 문장별 근거 펼치기. 복사·파일 받기는 줄이 겹치지 않게 배치한다.
- 각 채널의 미작성/작성됨/확인 필요를 텍스트로 표시한다. 검증 전 초안 복사는 버튼 이름과 복사 본문 모두에서 구별한다.
- 재작성은 기존 문서 옆의 제안으로 제시한다. 변경 부분·수치·조건을 비교한 후 적용한다.
- 실제 후기 없음은 ‘후기 촬영 가이드’, 발표 없음은 ‘발표 내용 확인 전 초안’, 대본 없음은 ‘영상 제작 전 초안’으로 구별한다.
- ‘준비된 문서 N개’는 실제 문서 개수. 정확도·성과 점수로 오인할 그래프는 넣지 않는다.

## 실행 순서와 통과 기준

| 순서 | 작업 | 이번 상태 | 통과 기준 |
|---|---|---|---|
| D0 | 레퍼런스 확인, DESIGN.md, 화면·모션 명세 | 작성 | 근거와 자체 설계의 구분, 실제 코드와 연결된 작업 목록 |
| D1 | 공통 색·간격·입력·헤더와 첫 화면 | 구현·검수 대상 | 원래 프로젝트 생성·수정·수동 경로 보존, 모바일 가로 넘침 없음 |
| D2 | 분석 5개 요약 + 근거 펼치기 | 다음 작업 | 비교 가능 조건·약점·가설이 실제 데이터와 일치, 0건/실패 구분 |
| D3 | 결과 편집·근거 병렬·채널 상태·재작성 제안 | 다음 작업 | 편집 중 문구 보존, 현재 버전 검증, 복사/파일과 화면 일치 |
| D4 | 실제 실행 상태 모션·모바일/접근성 전수 검수 | 다음 작업 | fake progress 없음, reduced motion, 키보드·초점·200% 확대 |

D2~D4는 W3~W6의 로직 보완과 함께 진행한다. W4 자동 실행의 결과 반영·비용 정산·인증 UI가 완성되지 않은 동안 자동 실행은 계속 차단한다.

## 디자인 검수

- 320·375·390·768·1280·1440px에서 입력, 선택, 펼치기, 주요 행동에 접근 가능.
- 주요 버튼 44px 이상, 모바일 입력 16px 이상, 라벨 연결, 키보드 초점, 긴 한글·URL 줄바꿈.
- 체크박스·라디오에 텍스트 입력의 전체 너비 스타일이 적용되지 않음.
- 200% 확대와 reduced motion에서 내용 손실 없음. 기기/브라우저 검수 결과를 각각 기록.
- 최초 사용자에게 설명 없이 ‘새 작업 → 분석 확인 → 선택 채널 문구 복사’를 해 보게 하고 막힌 지점 기록.
- 디자인 선호 검수와 사실·조건 보존 검수를 분리. 보기 좋다는 평이 근거 검증을 대신하지 않음.

## 회장님 판단이 필요한 사항

지금 개발을 막는 디자인 질문은 없다. 1차 화면에서 **너무 차갑거나 밋밋한지, 중요한 내용이 먼저 보이는지, 휴대폰 입력이 편한지**를 검수받는다. 기존 D1~D3 중 실연결 계정·예산과 실제 대표 제품은 해당 검수 직전에만 필요하다. ORIGIN 이름 변경·새 로고 제작은 현재 범위에 넣지 않았다.
