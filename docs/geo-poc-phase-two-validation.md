# PoC 2단계 재개 검수 기록

작성일: 2026-10-28 KST. 상태: 구현 검수 진행 중. 실제 모델의 분석 품질과 PoC 2단계 전체 완료는 미판정.

## 현재 구현

소비자 발췌를 원본 행·출처·스냅샷에 연결하고 소비자 전용 질문 발견 요청문을 만든다. 실행별 입력·모델 확인 수준·요청문·응답·실패·사람 검토·기각 이력을 보관한다. 질문 후보는 왜 나왔는지, 어떤 원문이 지지하는지, 다른 해석과 표본 제한이 무엇인지를 보여준다.

후보는 `questionCandidates`에 별도 보관하며 기존 작성용 `project.questions`로 자동 전달하지 않는다. `isAcceptedDiscoveryCandidate`가 현재 근거·원본 응답·사용자 검토의 일치를 재검증하는 분석 사용 경계다. 질문 후보 수용이 제품 적합성·시장 대표 니즈·미충족 수요·GEO 성과를 승인하는 것은 아니다.

## 실제 원자료

`data/poc-consumers/public-excerpts-20261028.json`은 실제 직접 열람한 공개 작성물의 최소 발췌 12건이다. 질문 후보나 정답 분석은 포함하지 않는다. `collection-ledger-20261028.json`에 URL·게시일·확보 구간·발췌 SHA-256·실패 경로·한계를 남겼다.

- 풀리오 6건, 82cook 5건, 퀘이사존 1건. 3개 게시 경로라는 사실만으로 독립성·대표성을 인증하지 않는다.
- 2019~2026 자료가 혼재하며 현재 트리플체어2 슬림의 모델별 구매 수요나 적합성으로 일반화하지 않는다. 풀리오 편중과 긍정 후기 편중이 남아 우선순위 확정에 부족하다.
- 본문은 건강 상세·사용자명·IP·사진을 제외한 최소 구간이다. 원문 페이지 전체를 확보한 것으로 표시하지 않는다. 게시자·구매·발언의 진위 인증이 아니다.
- 체험단 표기는 보존한다. 나머지도 보상·상업적 이해관계 미확인을 독립 구매로 바꾸지 않는다.
- 직접 열람이 실패한 82cook 2개 글, 렌트리 및 robots 차단 경로는 검색 발췌로 수집 완료를 대체하지 않았다.
- 묶음 가져오기에서 외부 제공·공개 이용·비식별 검토는 false다. 공개 열람을 외부 제공 동의로 간주하지 않는다. 사용자가 선택 행의 권한·원문 범위를 확인해야 해당 행만 발견 요청에 들어간다.

## 검수의 구분

단위 시험의 소비자 질문과 AI 응답은 허구 또는 사람이 만든 입력이다. 실제 공개 발췌를 쓰는 UI 시험에서도 응답 JSON·권한 클릭·수용 클릭은 사용자 동작 시뮬레이션이다. 실제 외부 AI가 독립적으로 질문을 발견했거나 회장님/전문가가 의미를 승인했다는 시험이 아니다.

실제 모델의 질문 발견 능력·누락·유형 분류·맥락 해석·순서 안정성은 실제 요청문과 원본 응답을 확보하고 별도로 검토해야 한다. 현재 그 결과를 만들거나 통과로 표시하지 않았다. 이 대화의 개발 모델을 별도 소비자 분석 실행으로 소급 기록하지 않는다.

첫 구현 SHA e30ec7eb9b0fae97f8e82624b5f68aa5fe0c2acc의 CI 40603753679는 단위 141개 통과, UI 20개 통과·8개 실패, build 미실행이었다. 신규 4개는 통과했으나 기존 소비자 폼 중복·입력란 이름 부분 일치로 8개가 실패했다. 실제 화면 중복과 새 입력란 이름을 수정했으며 보완 SHA의 원격 전체 검수를 대기한다. 로컬 단위 143개·lint·typecheck 통과.

## 수동 실제 분석 실행 방법

1. 테스트 브랜치를 로컬 실행(`npm ci`, `npm run dev`)하고 프로젝트의 분석 화면에서 ‘소비자 원문에서 질문 발견’을 연다. 운영 배포는 수행하지 않았다.
2. ‘공개 소비자 발췌와 출처 연결’에서 위 JSON을 가져온다. 수집 범위·개인정보 제외·이해관계와 사용 권한을 검토한다. 기존 파일 행도 저장된 출처와 대조해 연결할 수 있다.
3. ‘기존 파일 행에 원문 출처 연결’에서 검토한 행을 선택하고, 비식별 검토 이유와 각각의 사용 권한을 지정한 뒤 ‘선택 행의 권한·비식별 검토 저장’을 누른다. 다른 행을 일괄 허용하지 않는다.
4. 원자료 행과 실제 사용할 서비스·화면 표시 모델·공개된 버전만 기록해 실행을 만든다. 미공개 버전을 추측하지 않는다. 제외 행과 사유를 확인한다.
5. 제품 정보·기존 사전 질문이 없는 새 대화에서 요청문을 수동 실행한다. 앱의 복사 상태는 실제 서비스의 전송/실행 완료 증명은 아니다. 서비스 모델/버전과 이전 대화의 영향은 직접 확인할 수 있는 범위만 기록한다.
6. 외부 서비스의 원본 응답을 편집하지 않고 붙여넣는다. 형식·중단·누락 오류도 원본 시도로 보관한다. 보완/재실행은 새 실행 또는 새 응답 시도로 남긴다.
7. 실제 질문/재구성/가설, 인용 위치, 상황·과업·장애·기대 결과, 다른 해석, 상충과 표본 한계를 대조한 뒤 후보를 검토한다. 수용하지 않는 후보도 원문과 사유를 남긴다.
8. 같은 소비자 자료의 역순·해시 순서를 별도 실행해 결과의 차이를 검토한다. 배열 첫 항목을 최우선 질문으로 선정하지 않는다.

## 남은 완료 조건

표본 편중·독립성·시점 범위를 보완하고, 허용된 실제 외부 모델 실행을 보존한 뒤 모든 수용 후보의 원문 지지와 해석을 검수해야 한다. 입력 순서·경로 제외에 따라 질문 묶음과 검토 우선순위가 달라지는지도 실제 결과로 확인해야 한다. 이 조건이 없으면 기능 검수만 통과하며 PoC 2단계 전체 완료는 보류다.

기존 콘텐츠 작성·Word 생성·결과 페이지·서버 유료 pipeline·운영 SQL·CI workflow·의존성 파일은 시작 기준과 코드 차이가 없다. main 병합·운영 DB/환경변수 변경·운영 배포·유료 API 호출은 하지 않았다.
