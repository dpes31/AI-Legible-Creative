Next.js 16.4.2·React 19로 올렸습니다. 이전 14.x 기반은 이 브랜치에서 확장하지 않습니다. 수동 보관은 IndexedDB, 서버 후보는 Supabase입니다. 서버 SQL은 별도 검수 프로젝트에만 적용하도록 준비했으며 어떤 실제 DB에도 적용하지 않았습니다. 운영 환경·메인 브랜치 변경은 승인 전 금지합니다.

미확정 외부 조건: 개인 인증 계정과 Supabase 검수 프로젝트, OpenAI 계정/가격·시험 예산, 실제 업무 사례, Vercel Preview 접근 보호. 이 조건 없이 수동 경로 개발과 모의 검증을 계속합니다.

## 2026-10-26 소비자 자료 가져오기 기준

- CSV·TSV·TXT·XLSX는 현재 브라우저 IndexedDB 작업에 저장합니다. 원본 행의 파싱된 각 셀, 원본 행 번호, 파일 해시, 데이터 유형, 제공자, 시장, 기간, 표본 범위, 지표, 단위, 절대/상대/추정 성격을 보관합니다. 원본 업로드 바이너리는 저장하지 않습니다.
- 기본값은 외부 AI 전달 안 함, 공개 콘텐츠 근거 사용 안 함입니다. 두 권한은 서로 독립이며 각 동의 여부를 저장합니다. 공개 사용을 허용하지 않은 원문과 해당 행에서 파생된 질문은 작성 요청문으로 넘기지 않습니다.
- 실제 질문 문구, 검색 도구의 키워드, 검색량/지수는 다른 자료 유형으로 취급합니다. 검색량 또는 키워드 관계 자료만으로 생성형 AI에 실제 입력한 프롬프트의 빈도나 전체 시장 수요를 단정하지 않습니다.
- 이 단계는 소비자 자료를 보존하고 외부 조사로 연결하는 기능을 구현합니다. 자료의 대표성·수집 권한·검색 도구 해석과 실제 니즈 발견 타당성은 자료 원본과 사용자가 검수해야 하며, 자동 성과로 표시하지 않습니다.

## 2026-10-28 PoC 1단계의 근거 승인 경계

- 기존 Source/Claim 계약에 호환 가능한 스냅샷·보류·의미 검토 필드만 추가했다. IndexedDB 버전 변경이나 운영 DB migration은 없다. 기존 자료를 삭제하거나 SHA를 자동 소급 생성하지 않고 보류 후 원출처 재대조를 요구한다.
- 승인 함수가 동기이므로 브라우저/서버 공통의 @noble/hashes 2.4.0 SHA-256을 고정했다. FNV를 전체 교체하지 않고 원문과 스냅샷을 별도 비교한다. Node crypto 및 WebCrypto 기준값 시험을 유지한다.
- 검토 지문은 고정 필드 순서로 계산하여 스키마 파싱의 객체 key 정렬에 영향을 받지 않는다. 해시를 발행자 인증이나 효능·니즈 의미의 증거로 취급하지 않는다. 숫자/단위는 보수적으로 대조하며 자동 판정 불가 또는 지원하지 않는 표기는 보류한다.
- 질문 발견과 경쟁 분석은 추가하지 않았다. 기존 분석·저장·재사용 경계에서 낡은 supported 값을 신뢰하지 않는 방어만 추가했다. 콘텐츠 작성/Word 생성 모듈은 수정하지 않았다.
- 실제 UI 자료는 출처를 재확인한 최소 발췌다. 후기의 건강·식별정보는 제외하고 부분 수집 범위와 미확인 권한을 유지한다. 전체 수집·구매 인증·대표성·독립 검증은 주장하지 않는다.
- XLSX CRC 검사 전에 ZIP 디렉터리의 크기 한도를 확인하도록 순서만 보강했다. 한도 내 CRC 검사는 유지하고 합성 초과 ZIP·CRC 오류 회귀를 둔다.
