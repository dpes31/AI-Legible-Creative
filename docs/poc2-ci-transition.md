# PoC2 자료 분리 검증 환경 전환안 — 2026-10-29

역사 기록: 아래는 원격 반영 전 제안과 당시 제약이다. 이후 `1977a7c`로 같은 Tree·부모의 커밋을 반영했고 두 원격 CI가 통과했다. 현재 기술 검증은 사용자 감리로 종료됐으며 [기술 종료 기록](poc2-technical-closeout.md)을 기준으로 한다. 아래 미실행·승인 대기 문구를 현재 상태로 해석하지 않는다.

현재는 원격 반영 전 검증 후보다. Push·Actions 실행·자동 Preview·실제 모델 분석을 실행하지 않았다. 최종 회귀 검증 완료는 보류한다.

## 현재 상태 재확인

이번 작업공간에는 이전 보고의 7e26670 커밋 객체와 제한 보존 폴더가 없다. 확인한 기존 작업 HEAD는 2729217이고, 실제 자료 9개 파일은 기존 코드 작업 폴더에 다시 존재한다. 이전 세션의 임시 보존 상태를 지속 보존의 증거로 사용할 수 없다. 원인을 확정하지 않으며 이전 성공 기록을 현재 SHA의 결과로 전용하지 않는다.

기존 로컬 장부와 재대조한 파일 9/9의 바이트 해시는 일치한다. 원본·장부의 파일 접근은 0600, 관련 하위 디렉터리는 0700으로 제한했다. 원자료는 외부로 전송하지 않았다. 개인정보 값을 수집하거나 패턴 전수 검사를 재실행하지 않았다.

실제 원격 테스트 브랜치는 de5f1b3c18f57e1ffb0c7ad8cf6eb16bdaa488cf이며 Draft PR #2는 open/draft/미병합이다. main은 62bb391a8b60a348006ccd09d74da0c6010039a9이다. 원격 기본 트리와 기존 로컬 복구 기준 트리는 일치하지만 커밋 이력이 갈라져 있다. 기존 로컬 이력을 강제로 Push하지 않는다.

## 원자료 보존과 관리 결정

자료 9개와 대응 장부는 PoC2 검수 재현·인용 대응·향후 적법한 이용 여부 결정까지 지속 보존이 필요하다. 영구 보관을 무조건 가정하지 않으며 PoC2 종료 시 필요성을 다시 결정한다.

권고 관리 주체는 사용자가 지정한 자료 책임자다. 책임자 소유의 암호화된 로컬 디스크에서 Git·자동 동기화 폴더 밖의 접근 제한 폴더를 우선 권고한다. 현재 도구로 사용자 PC의 암호화·권한·백업·보관기간은 확인할 수 없다. 확정된 책임자·경로·이관 경로는 아직 없으므로 지속 보관 확보로 표시하지 않는다.

이관 시 원본 폴더 구조와 ID·본문 범위·대응 장부·파일/발췌 해시를 유지하고, 사용자가 승인한 직접 이관 경로만 사용한다. 수신 측에서 파일 9개 및 발췌 21개의 해시·대응 확인 후 인수 기록을 남긴다. 기존 임시 자료 삭제는 별도 확인 후 결정한다. 원본/대응 장부를 Public GitHub·외부 클라우드·Library·AI 서비스에 새로 업로드하지 않는다. 지금은 기존 로컬 원본을 보존하고 검증용 코드 후보에는 원자료를 복사하지 않았다.

## 실행 환경 선택

| 경로 | 확인 상태 | 판단 |
|---|---|---|
| 기존 브라우저 가능 개발환경 | 연결된 대체 환경·담당자·사용 가능 여부 미확인 | 사용자 지정 환경이 있으면 가능하나 현재 즉시 실행 경로 아님 |
| 기존 GitHub Actions | Ubuntu runner, Node22, 브라우저 설치, 28개 UI, build 절차 존재 | 권고. 새 플랫폼 추가 없이 기존 검증 절차 활용 |

소켓·라이브러리 복구를 다시 시도하지 않는다. 현재 원격 워크플로를 재실행하면 아직 실제 자료를 읽는 과거 시험을 돌리므로 재실행하지 않는다. 먼저 허구 Fixture·공개 경계·자료 제거를 포함하는 검토 후보를 별도 승인 후 기존 테스트 브랜치에 반영한다.

## 재구성한 후보의 범위

원격 de5f1b3 바로 다음에 연결되는 로컬 준비 브랜치에서 2729217의 허구 시험/경계 구현을 재사용했다. 실제 자료 9개 파일은 checkout 전에 후보 index에서 제외하여 검증 후보 폴더에 원문을 복사하지 않았다. 기존 원본 작업 폴더와 Git 이력은 보존했다. 후보만 실제 자료가 없는 최신 코드 트리를 갖는다. 기존 원본 폴더의 지속 보관 문제는 분리하여 미해결로 표시한다.

추가 변경은 실제 자료 경로의 .gitignore 재유입 방지와 CI의 검증 SHA 고정이다. checkout은 PR에서는 pull_request.head.sha, Push에서는 github.sha를 사용하고 git rev-parse HEAD와 기대 SHA를 대조·기록한다. PR의 자동 merge commit을 후보 HEAD 시험으로 혼동하지 않는다. 앱 로직·작성/Word·시험 assertion·시간 제한·브라우저 설정·147개 단위 및 28개 UI 시나리오는 바꾸지 않는다.

## 같은 SHA의 검증 절차

1. 원격 현재 HEAD가 승인 시점 기준과 일치하고 후보의 조상인지 확인한다. 다르면 전송하지 않고 다시 검토한다.
2. 승인받은 후보 커밋만 기존 refactor/evidence-workflow-v2에 일반 fast-forward Push한다. main·PR 상태·이력·공개 범위는 변경하지 않는다.
3. Actions checkout 실제 SHA를 기록한다. npm ci 후 전체 공개 경계, lint, typecheck, 전체 단위시험, Chromium/WebKit 기본 설치 및 UI28개, build를 같은 소스에서 수행한다. 실제 checkout SHA와 모든 결과를 묶어 제출한다.
4. 전용 public-test-results만 출력 검사한다. 입력 manifest·원문 경로 참조·trace 압축 내부 텍스트를 검사하고 정상/보류/재열기 화면을 시각 확인한다. PNG는 자동 OCR 검사 통과로 표시하지 않는다. 실제 원문을 CI로 보내 대조하지 않는다. 검토된 허구 입력만 사용한다.
5. 경계 통과 시에만 산출물을 업로드한다. 성공 시 UI28개, 실패 시 시험 단계/설치 환경/앱 assertion 오류를 구분한다. 실패를 숨기거나 기대값을 낮추지 않는다. 코드 수정이 필요하면 새 SHA의 전체 요구 검증을 다시 수행한다.

Push와 pull_request 이벤트가 함께 발생하면 두 workflow run이 생길 수 있다. 둘 다 같은 명시적 HEAD를 checkout하는지 확인하고 run ID와 checkout SHA를 보고한다. 과거 de5 CI/Vercel success를 새 후보의 결과로 사용하지 않는다.

## Push와 Preview 영향 및 승인 요청 범위

Vercel 프로젝트 ai-legible-creative와 원격 de5의 Vercel success 상태를 확인했다. 프로젝트 요약에는 비커스텀 도메인 SSO 보호가 활성화되어 있다. 상세 배포 조회는 팀 권한 부족으로 확인하지 못했으며 새 권한 승인·보호 설정 변경은 하지 않았다. 현재 세부 Git 자동 배포 예외 설정은 미확인이다. 따라서 Push는 자동 Preview 생성 가능성을 포함해 승인받아야 하며 Preview 미생성을 보장하지 않는다.

Vercel 기본 Git 연동은 비운영 브랜치 Push에 Preview 빌드·URL을 생성한다. Preview는 Actions와 별도로 진행될 수 있어 CI 실패가 Preview 생성 중단을 의미하지 않는다. PR의 배포 상태/링크, 빌드·실행 리소스, 기존 Preview 환경 설정이 사용될 수 있다. 기존 워크플로는 Vercel 배포 명령을 호출하지 않지만 Git 연동 자체의 자동 동작은 별개다.

요청하는 별도 승인은 준비 후보의 기존 테스트 브랜치 Push, 그에 따른 자동 Preview 가능성, 기존 Actions의 허구 회귀 검증에 한정한다. 운영 환경변수·DB·배포 보호·production alias 변경, main 병합·운영 배포·유료 AI API·실제 모델 분석·원자료 외부 전송은 포함하지 않는다. UI 시험은 127.0.0.1의 새 서버에서 허구 입력으로 실행하며 Preview에서 실제 분석 API를 호출하지 않는다.

## 현재 결과와 남은 과제

후보 SHA를 확정한 뒤 수행한 로컬 결과는 별도 사용자 보고서에서 실제 SHA와 연결한다. 승인 전 원격 CI 및 UI 정상 실행 결과는 없다. 현재 검증 후보의 자료 분리와 원자료 지속 보관은 서로 다른 판정 항목이다. 최종 완료에는 지속 보관 결정, 같은 SHA에서 공개 경계·lint·typecheck·단위·build·UI28개 정상 실행·산출물 재유입 확인이 필요하다.

원격 회귀 검증 후 B안 실제 질문 발견 품질 검증으로 복귀한다. 권한 근거·관리 주체·정확한 전송 ID/해시·비식별 범위·허용 계정·모델/환경·보관 위치에 대한 별도 승인 전 실제 소비자 원문 전송이나 모델 실행은 하지 않는다. PoC2 전체 완료·PoC3 진입은 계속 보류한다.
