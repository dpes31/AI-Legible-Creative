# 소비자 질문 발견 PoC 설계

실제 질문 표현·원문 기반 재구성·AI 탐색 가설을 구분하고 정확한 원문 구간, 상황·과업·장애·기대 결과와 다른 해석을 함께 검토한다. 제품 기능·기존 질문·사람의 분석 결론은 발견 입력에서 제외한다.

## 재사용 경계

consumer-evidence의 저장/참조 연결, question-discovery의 요청/응답 보존, discovery-integrity의 승인 재검증, 기존 저장·재열기를 사용한다. 출처 ID나 SHA 일치만으로 의미를 승인하지 않는다. 정보 부족·상충·가설·원문 불일치는 정상적인 보류 결과다.

실행별 입력·모델 확인 수준·순서·요청문·원본 응답·실패/검토 이력을 보존한다. 발견 후보는 작성용 질문 배열로 자동 전달하지 않는다. 최초 후보나 배열 순서로 우선순위를 선정하지 않으며 독립성·편향·시점의 한계를 별도로 표시한다.

## 공개 회귀와 실제 품질 검수

공개 단위/UI 시험은 명시적인 허구 발언·허구 응답·동작 시뮬레이션을 사용한다. 실제 데이터는 별도 이용 근거·보관 위치·전송 승인 후 제한 환경에서 검수한다. 실제 모델의 발견·누락·해석 품질은 허구 회귀 통과와 구분한다.

실제 자료의 출처·본문·권한/개인정보 대응표와 실행 원본은 공개 개발 문서에 두지 않는다. 보관 승인 전 원자료의 기존 로컬 파일 정리는 보류하며 최신 트리 공개 준비 검사는 이를 차단 상태로 보고한다.

PoC3·작성/Word 확장·main 병합·운영 배포·유료 API는 승인 범위 밖이다.
