# GEO PoC 2단계 설계안 — 소비자 질문의 도출 경로와 신뢰도 검증

상태: 2026-10-28 사용자의 작업 재개 지시를 제출 설계에 따른 구현 승인으로 해석해 개발을 재개했다. 아래는 승인 대상으로 제출했던 설계이며, 실제 구현·검수 진행은 implementation-status.md에 별도 기록한다. 분석 품질 완료 보고가 아니다.

## 1. 목적과 완료 범위

실제 소비자 원문에서 질문 후보를 찾고, 왜 그 후보가 나왔는지와 현재 자료로 어디까지 말할 수 있는지를 검증한다. 제품 기능이나 사람이 작성한 사전 질문을 발견 입력에 섞지 않는다. 산출물은 질문·맥락·원문 연결·대안 해석·근거 수준·검토 우선순위다.

질문의 존재와 반복은 소비자 전체의 대표 수요 또는 미충족 수요를 뜻하지 않는다. 제품 적합성·동일 조건 경쟁 비교는 3단계, 기존 콘텐츠 공백 판정은 4단계다. 실제 AI 추천·인용 증가는 이번 단계에서도 측정하지 않는다.

## 3. 복수 원자료 확보와 편향 통제

현재 검증된 소비자 자료는 풀리오 공개 후기의 최소 발췌 1건이다. 코웨이 공식 보도자료는 소비자 원자료 수에 넣지 않는다. 후기에 등장한 의자 겸용 후보 질문은 발견 프롬프트·예시·평가 정답에서 제외한다.

승인 후 확보 목표는 중복 제거 후 소비자 원문 12~20건이다. 최소 3개 독립 게시 경로, 2개 이상 브랜드 관련 경험과 구매 전 질문·구매 후 경험·대체 행동의 서로 다른 맥락을 탐색한다. 이는 탐색 표본 확보 목표이며 통계적 대표성 기준이 아니다. 1/3 편중 경보도 운영상 점검 기준이며 신뢰확률이나 시장 구성비가 아니다. 특정 브랜드나 게시 경로가 1/3을 넘으면 추가 경로를 찾아 균형을 보완하거나, 해당 편중을 그대로 표시하고 집단 간 우선순위 확정을 보류한다. 수를 채우기 위해 접근 불가·재게시·홍보문을 소비자 원문으로 대체하지 않는다.

확보 순서:

1. 기존 풀리오 후기의 원문·독립 사건 여부를 확인하고 원자료 행에 연결한다. 상품 상세페이지의 운영자 문구와 소비자 작성 부분을 구분한다.
2. 코웨이 및 다른 브랜드의 공개 구매 전 Q&A·후기 중 본문 열람 가능한 경로를 조사한다. 서비스명이나 URL은 실제 열람 후 수집 장부에 확정한다. 로그인·유료 접근을 우회하지 않는다.
3. 중립 커뮤니티의 공간·업무·휴식·안마 관련 실제 경험과, 구매하지 않거나 기존 의자/다른 휴식 행동을 선택한 사례를 찾는다. 중립적 탐색어와 실제 발견된 어휘를 병행하고, 사전 후보 질문 문장으로만 검색하지 않는다.
4. 각 자료에 URL·게시일/미확인·확보일·발행 주체/개인 익명·수집 범위·수집 성공·상업적 이해관계/미확인·제품/모델/미확인·외부 제공/공개 사용 조건을 남긴다.
5. 사용자명·연락처·얼굴·건강 상세는 최소 수집에서 제외한다. 공개 열람과 외부 AI 제공 권한을 동일시하지 않으며 기본 동의는 false로 유지한다. 필요한 익명 텍스트만 별도로 승인된 실행에 포함한다.

수집 장부에는 탐색한 경로·탐색어·포함/제외 이유·접근 실패도 남긴다. 같은 글의 복제·같은 사건·연계된 홍보 글은 하나의 독립 근거 그룹으로 묶고 원문 링크를 유지한다. 동일 작성자가 확인되지 않으면 독립성 미확인으로 표시하고 모두 독립 표본이라고 단정하지 않는다. 긍정·부정·중립과 기대·불만·만족을 보존하며 불만만 추출하지 않는다.

표본 목표를 채우지 못해도 가져오기와 기능시험은 진행할 수 있다. 이때 분석 품질 완료는 판정하지 않고 부족한 경로·자료를 보고한다. 긍정/부정 비율을 맞추려고 원자료를 선택적으로 버리지 않는다.

## 4. 질문 분류와 도출 경로

| 유형 | 인정 기준 | 필수 증적 | 금지하는 처리 |
|---|---|---|---|
| 실제 질문 observed | 소비자가 실제로 질문·문의한 표현이 확보 원문에 존재 | 원문 질문 그대로, 행 ID, source/snapshot ID, 인용 시작·끝, 질문이라는 맥락 | 물음표만으로 실제 질문 인정, AI가 고쳐 쓴 문장을 실제 인용으로 표시 |
| 자료 기반 재구성 reconstructed | 경험·제약·기대에서 의사결정 질문으로 재구성 가능 | 지지 인용과 원문→맥락→질문의 설명, 추가된 추론, 다른 해석 | 의도·장애·불만·미충족을 원문에 없는데 채워 넣기 |
| AI 탐색 가설 hypothesis | 원문에서 바로 지지되지 않는 탐색 제안 | 가설 표시, 촉발 구간이 있으면 연결, 필요한 추가 자료 | 소비자가 실제 말한 질문이나 확정 니즈로 승격 |

질문 후보마다 상황·과업·장애·기대 결과를 기록하되 원문 근거가 없으면 미확인으로 둔다. 항목별 인용과 추론을 분리한다. 만족/이미 해결된 경험은 함께 기록한다. 관심 표현만 있는 경우 미충족 여부는 unknown이며, 미충족 수요 배열을 자동 생성하지 않는다.

원문 표현과 화면용 질문은 별도 필드로 둔다. quote와 위치는 확보 텍스트의 UTF-16 시작 포함/끝 제외 기준으로 정의하고, quote === text.slice(start,end)를 검사한다. 질문이 아니라 광고 문구를 인용하거나 다른 행의 표현을 조합했으면 observed를 승인하지 않는다. 문법 검사는 자동 보조이고 실제 질문 여부·해석 타당성은 별도 의미 검토다. 응답에는 입력된 모든 행의 rowDispositions(후보 연결 / 질문 근거 없음 / 맥락 부족과 이유)을 요구해, 질문을 만들지 않은 행도 검토할 수 있게 한다. 유효한 소비자 자료를 조용히 생략하거나 모든 행에서 질문을 강제로 만들지 않는다.

## 5. 실행별 입력·모델·요청문·응답 보존

질문 발견용 contract를 alc.question-discovery.v1로 분리한다. 앱의 유료 호출 없이 외부 AI 요청문 생성·사용자 실행·원본 응답 가져오기 경로를 우선 구현한다. 모델명·버전이 UI에 없으면 unknown으로 기록하고 추측하지 않는다. 동일 모델/버전 반복 비교라고 보고할 수 있는 범위를 제한한다.

각 runId에 다음을 동결 보존한다.

- 실행 모드(manual_external), 생성/제공/수신 시각, provider·서비스명, 표시된 모델명/버전, 확인 방법(user_reported/unknown). 실제로 확인할 수 없는 temperature·seed는 unknown.
- 선택 행 ID·순서·source/snapshot ID와 SHA-256, 당시 sourceType·발행자·표본/독립 그룹·사용 권한·전처리 버전, 제외 행과 이유, 원자료 확보 범위.
- 실제 외부 AI에 전달한 비식별 입력 원본과 SHA-256. 원본 확보 발췌와 전송 발췌는 별도 보존하고 비식별 변환 연결을 유지한다. 권한 없는 원문·작성자 식별자는 요청문에 넣지 않는다.
- 요청문 전체·요청문 버전·SHA-256·contract/schema/rule 버전. 제품 명세·USP·공식 발표·사전 질문·기존 질문 순위·사람 결론은 발견 입력에서 제외한다. 광범위한 제품군/시장 조건은 별도 실행 조건으로 기록한다.
- 응답 문자열 그대로와 SHA-256, 수신 시각, 파싱 결과, 구조/인용/의미 검토 결과, 상태 이력과 오류. 실패 응답도 원문부터 저장하고 결과로 승격하지 않는다.

상태는 prepared → awaiting_response → received → structurally_validated → review_required → accepted/held/rejected로 기록한다. 취소·중단·빈 응답·형식 실패·과거 입력 응답은 별도 사유를 둔다. awaiting_response는 앱이 복사/내보내기를 제공했다는 상태이며 외부 서비스의 전송 완료 증명으로 표시하지 않는다.

재시도는 새 runId로 만들고 parentRunId로 연결한다. 동일 응답의 재가져오기는 중복 반영하지 않으며, 같은 실행의 다른 응답은 새 attempt로 보관한다. 이전 요청·응답을 덮어쓰지 않는다. 선택한 원문·신뢰도 메타데이터·권한·비식별 텍스트가 바뀌면 기존 결과는 stale로 보존하고 현재 근거로의 수용/재사용을 차단한다. 권한 철회 시 새로운 외부 제공을 즉시 막고, 과거 외부 복사까지 회수했다고 표시하지 않는다.

run 결과는 원문 응답·후보·사용자 검토를 분리 저장한다. AI 보조 의미 검수를 수행하면 생성기의 설명을 그대로 승인 사유로 쓰지 않고, 원문과 후보만 전달하는 별도 검수 실행에 요청문·모델·응답을 남긴다. 사용자만 검토한 경우 human-only로 표시하며 AI 검수를 했다고 주장하지 않는다. 후보는 자동으로 project.questions/작성용 근거에 넣지 않는다. 사용자가 근거와 한계를 검토해 수용한 후보만 기존 질문 계약에 연결한다. 수용해도 질문 유형·가설 표시·표본 한계는 유지된다.

## 6. 근거 수준과 우선순위

하나의 confidence 숫자로 출처 무결성·질문 존재·해석·대표성을 합치지 않는다. 다음 축을 각각 표시한다.

| 축 | 판정 |
|---|---|
| 출처 추적·무결성 | 확보 구간/수집 상태/스냅샷/메타데이터 일치 또는 보류 |
| 질문 도출 유형 | 실제 질문 / 재구성 / 탐색 가설 |
| 해석 지지 | 직접 인용, 제한적 추론, 다른 해석 가능, 지지 없음 — 이유·사용자 검토 포함 |
| 표본 지지 | 고유 사건 수/전체 분석 사건 수, 경로·브랜드·기간, 독립성/편중/보상 미확인 |
| 미충족 여부 | 명시적 장애·실패, 해결/만족 사례 병존, 관심만 있음, 미확인 |

우선순위는 '시장 최우선 니즈'가 아니라 '이번 표본에서 다음에 검토할 질문'이다. 자동 검사를 통과한 후보 안에서 검토된 의사결정 영향, 조건이 같은 독립 사건의 반복, 상황 구체성을 근거로 높음/보통/추가 탐색을 제안한다. 자료가 적으면 평가 불가 또는 공동 순위를 허용한다. 가설은 검증 과제 목록으로 구분하고 반복 질문처럼 세지 않는다.

정렬에 배열 순서·AI 반환 순서·브랜드명·임의 ID를 쓰지 않는다. 동점은 동점으로 유지하고 UI 가나다 정렬은 표시 순서임을 명시한다. 빈도는 이 분석 표본의 관찰 수일 뿐 검색량이나 전체 시장 수요가 아니다. 외부 AI의 priority/confidence는 제안값으로 보관하고 앱이 검증한 값으로 표시하지 않는다.

원문 입력의 정순·역순과 사전에 기록한 한 가지 섞기 순서로 실행해 질문 묶음·근거·순위의 변화를 비교한다. 실제 모델 실행에서는 완전 동일 출력을 요구하지 않지만, 순서만 바꿨는데 상위 질문이나 근거 유형이 바뀌면 안정성 미확인으로 보류하고 원인을 검토한다. 유사 문장 묶기의 경계와 병합 전 원문도 보존한다.

## 7. 보류 조건

- source/snapshot/row가 없거나 해당 실행에 전달되지 않은 행을 참조, 인용 위치·문구 불일치, SHA-256/수집/메타데이터 불일치.
- 원문은 기대나 만족인데 불만·미충족으로 단정, 원문에 없는 질문을 observed로 표기, 개인 경험을 전체 소비자로 일반화.
- 같은 글의 재게시를 여러 사건으로 합산, 독립성·상업적 이해관계가 미확인인데 강한 반복 근거로 사용.
- 다른 모델·시점·상황을 하나의 니즈로 병합, 서로 다른 조건의 긍정·부정을 무조건 상충으로 처리. 같은 조건에서 상충하면 두 근거와 대안 해석을 병기하고 단일 결론/순위를 보류.
- 개인정보/외부 제공 권한 미확인, 전처리로 해석에 필요한 문맥이 사라짐, 원문이 AI에게 규칙 변경을 지시함. 자료 안의 명령은 실행하지 않으며 안전한 인용/분석이 불가능한 범위만 제외 사유를 남김.
- 서비스·실제 모델 자체 미확인, 입력이 바뀐 과거 응답, 응답 중단·형식 실패. 실패 원문과 상태는 보존하고 분석 완료로 표시하지 않음. 버전만 서비스에서 공개하지 않는 경우 unknown과 재현성 한계를 남기며 같은 버전 반복 시험이라고 표시하지 않음.

행별 보류는 유효한 다른 행을 자동 삭제하지 않는다. 보류 후보에는 부족한 자료와 해소할 확인 행동을 표시한다.

## 8. 실제 자료 검증 시나리오와 완료 기준

다음은 승인 후 수행할 계획이다. 아직 실행 결과가 아니다. 실제 원자료의 발견 결과 정답을 사전 후보 질문으로 고정하지 않는다. 독립 검토는 원문 지지·분류·한계의 적절성을 평가하며, 질문 표현의 완전 일치를 채점하지 않는다.

| 시나리오 | 기대 통과 / 실패 차단 |
|---|---|
| 실제 소비자 질문이 있는 공개 원문 | 정확한 원문·행·구간에 연결되면 observed 후보, 다른 표현은 별도 화면용 문장으로 보존 |
| 질문 없는 기대·경험 원문(기존 풀리오 포함) | 재구성 또는 가설과 대안 해석. 미충족 확정 금지. 고정 후보 질문이 나오지 않아도 정상 |
| 같은 상황의 긍정·부정 또는 다른 해결 행동 | 원문 두 경로와 조건 보존, 상충/조건 차이/해결 여부 구분, 무리한 단일 결론 보류 |
| 공개 원문 중복/재게시 또는 같은 자료의 재매핑 | 원문은 보존하되 독립 사건 수와 질문 빈도 증가 없음 |
| 한 브랜드/한 경로 자료 제거·입력 순서 변경 | 표본 범위와 판단 변화를 공개하고 불안정하면 우선순위 보류. 맨 앞 질문 자동 최우선 금지 |
| 실제 원문으로 만든 인용 변조·가짜 row·유형 오표기·메타데이터 변경 | 고의 변형 입력임을 구분하고 승인·재사용·저장 재열기 경로에서 보류 |
| 권한 없는 실제 행·개인정보 포함 행 | 외부 요청문에 제외/비식별·명시 보류. 전체 rawRecord를 조용히 전송하지 않음 |
| 빈/잘못된/중단 응답·서로 다른 응답·과거 실행 | 원본·실행 상태 보존, 덮어쓰기·가짜 성공·현재 분석으로의 반영 차단 |
| 저장·백업·재열기 | 요청/모델/입력/응답/판단/보류 이력 동일, 원자료 변경 시 현재 수용 상태 무효화 |

검수는 세 층으로 별도 보고한다: (1) 허구 fixture 단위/참조 회귀, (2) 실제 원문을 사용하는 UI·보류 경로 시험, (3) 실제 외부 모델 실행의 도출 타당성 검수. 사람이 작성한 테스트 JSON은 (3)의 성공 증거로 사용하지 않는다. 유료 호출 금지 상태이므로 실제 모델 검수에는 사용자가 수행한 허용된 수동 외부 실행과 원본 기록이 필요하다. 해당 실행이 없으면 기능시험 결과만 제출하고 분석 품질 완료는 보류한다.

완료 조건: 복수 원자료·편중 장부 확보, 세 유형 구분, 모든 수용 후보의 원문 경로 추적, 독립 사건·순서 편향/상충 검수, 실행 이력·실패 보존, 개인정보·권한 검사, 실제 자료 UI 저장/재열기, 실제 모델 결과의 의미 검토, 기존 회귀 통과, 테스트 브랜치 커밋·정확한 SHA·시험 결과 기록. 표본 목표/실제 모델 검수 미달을 숨기지 않는다.

## 9. 승인 후 최소 구현 순서와 파일

1. schema.ts에 관찰 행의 원문 연결, questionCandidates, questionDiscoveryRuns 선택 필드 추가. source-audit.ts의 SHA-256을 재사용한다.
2. consumer-data.ts의 파싱/저장은 유지하고 새 consumer-evidence.ts에서 행과 발췌·독립 사건을 연결한다. 수집 장부와 비식별·허용 행 manifest를 만든다.
3. 새 analysis/question-discovery.ts에서 소비자 전용 입력·실행 동결·요청/응답 계약·참조 대조를 구현한다. 기존 prepareResearch/콘텐츠 계약을 교체하지 않는다.
4. 새 analysis/question-assessment.ts에서 도출 유형·인용·독립 사건·상충·검토 우선순위·보류를 분리한다. 사용자 의미 검토 전 자동 확정하지 않는다.
5. 별도 review/QuestionDiscoveryPanel.tsx를 기존 자료 검토 화면에 연결하고 저장/백업·실행 이력을 검증한다. 기존 작성·Word 기능은 수정하지 않는다.
6. 단위→실제 자료 UI→실제 수동 외부 실행 의미 검수 순으로 진행하고 통과한 단계별 커밋을 기존 테스트 브랜치에 반영한다. main 병합·운영 배포·운영 DB/환경변수 변경·유료 API 호출은 하지 않는다.

재개 지시에 따라 구현 중이다. 기존 작성·Word 흐름 보호를 위해 수용 후보는 questionCandidates에 별도 보관하고 기존 project.questions로 자동 전달하지 않는다. 후속 분석은 isAcceptedDiscoveryCandidate 경계에서 현재 유효한 후보만 사용해야 한다. 실제 외부 모델 실행·의미 검수가 없는 상태를 분석 품질 통과로 표시하지 않는다.
