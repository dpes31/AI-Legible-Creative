# 구현된 관계와 아직 남은 관계

수동 화면은 `Project` 한 개를 IndexedDB의 단위로 저장합니다. 제품 모델은 별도 입력이며 모델 변경 시 새 작업을 만듭니다. 주장은 출처 UUID를 참조하고, 문서의 블록은 주장 UUID를 참조합니다. 이전 localStorage 원본은 해시로 중복 감지하며 복제본을 남긴 다음 별도 프로젝트로 전환합니다. 출처의 정확한 인용 문자열을 본문에서 찾는 검사는 의미 검증과 별개입니다. 외부 AI 응답의 `verified`나 경쟁 우위 표시는 승인 상태로 가져오지 않습니다. 경쟁 비교 조건이 확인되지 않으면 제안된 우위는 보류하고 작성 요청문에서 제외합니다.

현재 수동 요청은 조사 `alc.research.v2` → **목표 질문·미충족 요구·근거·비교 한계·채널 방향을 한 번 검수** → 공통 `alc.brief.v1` → 작성 `alc.content.v2` 순서입니다. 과거 v1 응답도 가져올 수 있습니다. `ContentBrief`는 공식 URL·대상 모델·고객 질문·확인된 원문과 조건·비교의 미확인 상태·수정 의견의 버전을 함께 전달합니다. 피드백 속 새 사실은 방향 제안일 뿐 허용 주장에 들어가지 않습니다. 문서 편집은 해당 채널을 `stale`로 만들고 이전 버전을 보관합니다. 출처를 외부 AI에 보내는 허용과 공개 문구에 쓰는 허용은 별도입니다.

서버에는 Supabase Auth의 사용자 토큰으로 접근하며 RLS로 소유자별 조회를 제한하는 프로젝트 및 실행 테이블·SQL이 있습니다. 실행 예약은 DB 예산 행을 잠근 뒤 생성하며 단계 선점은 한 번씩 수행합니다. OpenAI 어댑터는 웹 검색 응답의 실제 인용과 별도 구조화 응답을 받도록 분리되어 있고, 모의 공급자 단위 검사가 있습니다. **실제 서버·계정 연결, 이 실행 결과를 프로젝트에 안전하게 반영하는 흐름, 재개·정산·채널별 검증은 아직 완성되지 않았습니다.** 비용 정산이 없는 상태에서 환경변수만으로 유료 호출이 켜지지 않도록 실행 경계 자체가 503을 반환합니다. 현재 자동 모드를 선택해도 사용자 화면은 수동 작업을 안내합니다.

현재 코드 검증은 숫자·인증·우위 키워드의 무근거 사용, 누락 조건, 자리표시자, 연결 ID와 채널별 본문 구조를 확인합니다. 개별 문단마다 버튼을 누르는 방식은 결과 화면에서 제거하고 중복 없는 핵심 주장과 채널 전체를 검토합니다. 수정하면 검증 상태가 무효화됩니다. 일반 서술문 속 모든 숨은 사실 주장·의미상 지지 여부·가격 조건 비교는 자동으로 완벽하게 검증되지 않습니다.

IndexedDB v3에는 입력 초안, 브랜드 프로필과 모델 카탈로그를 추가했습니다. `Project`에는 조사 이력, 인사이트 피드백 버전, 질문 답변 초안, 채널 문서 이력, 게시 원고 스냅샷과 URL, 게시 전/후 관찰을 보관합니다. 게시 URL 등록은 색인이나 인용이 아닙니다. 관찰 분모는 성공해 원본 답변을 기록한 건수이며 제공 자료 시험과 일반 검색 관찰을 합치지 않습니다. 원고 내보내기는 개별 TXT/MD 및 선택한 채널을 하나로 묶은 DOCX, ZIP 안의 단일 DOCX입니다. 기존 `origin-mvp-store`의 원본은 이전 완료 전 삭제하지 않습니다.

모의 단계 실행기는 요청 유실을 `uncertain`으로 남기고 자동 재호출하지 않으며, 조사 응답과 채널별 응답을 같은 도메인 가져오기 규칙에 넣어 검증합니다. 이것은 실제 DB 동시성·가격 정산 검증을 대체하지 않습니다. 실 API 호출은 서버에서 강제로 503 차단됩니다.
