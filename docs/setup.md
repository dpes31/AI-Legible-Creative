# 검수판 실행과 자료 옮기기

1. 저장소의 `refactor/evidence-workflow-v2` 브랜치를 받습니다.
2. Node.js 22 환경에서 `npm ci`, `npm run dev`를 실행합니다.
3. `http://localhost:3000`을 열고 가상 브랜드라도 이름·목적·고객 상황을 넣습니다. 직접 방식이 기본입니다.
4. 분석 확인에서 조사 요청문을 복사해 외부 AI에 보내고 응답을 붙여넣습니다. 오류는 가져오기 버튼 옆에 나오고 원문은 남습니다. 출처는 AI가 제시한 문장만으로 검증되지 않습니다. 실제 원문을 읽고 주장의 모델·조건을 대조합니다.
5. 핵심 인사이트의 목표 질문·미충족 요구·근거·한계를 확인하고 수정 의견을 적습니다. 확인 후 작성 요청문을 복사해 다시 보내고 결과를 붙여넣습니다. 수정 의견에 새 수치나 기능을 적었다면 근거 없는 사실로 공개하지 않습니다.
6. 채널별 원고를 검수·수정·복사합니다. 각 채널 TXT/MD 또는 모든 선택 채널을 묶은 Word 파일을 받을 수 있습니다. `검토용 초안`과 `자료 보완용 구성안`은 최종 공개본이 아닙니다. 질문·게시 콘텐츠 화면에서 게시 URL과 실제 원고 버전, 게시 전 시험과 게시 후 관찰을 별도로 기록할 수 있습니다.
7. 설정에서 현재 작업의 JSON 백업을 받습니다. 다른 주소의 검수판에서는 해당 파일을 가져옵니다. 운영 주소의 localStorage는 다른 Preview 주소에서 직접 읽을 수 없습니다. 예전 운영 앱에는 새 설정 화면이 없으므로 Preview에서 예전 원본을 자동으로 읽거나 내려받을 수 없습니다. 운영 주소에 새 버전을 배포한 **뒤**에는 같은 주소에서 원본을 백업하고 자동 이전할 수 있습니다. 운영 전 자료를 Preview로 옮기는 방법은 원본 파일을 먼저 확보한 경우에만 이용합니다.

개인 인증·클라우드 저장을 실제로 연결할 때는 별도의 Supabase 검수 프로젝트를 준비하고 `supabase/migrations/202610200001_evidence_v2.sql`을 검토 후 적용합니다. 공개 회원가입을 끄고 소유자 계정만 허용합니다. `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `ALLOWED_OWNER_EMAIL`은 해당 검수 프로젝트 값으로 **배포 환경**에 설정합니다. 세 값 중 하나라도 빠지면 서버 개인 작업이 열리지 않습니다. 실제 값을 Git·채팅·프로젝트 입력란에 붙여넣지 않습니다. 이 브랜치 UI는 아직 서버 프로젝트 동기화와 로그인 흐름이 완성되지 않았습니다.

OpenAI 연결 후보는 `OPENAI_API_KEY`, `OPENAI_RESEARCH_MODEL`, `OPENAI_WRITE_MODEL`, `OPENAI_VALIDATE_MODEL`을 서버 환경에 설정합니다. `PAID_EXECUTION_ENABLED=false`가 기본이며 계정·예산 D2 승인 전 변경하지 않습니다. 가격표 검토 날짜 `OPENAI_PRICE_CONFIRMED_AT`, 실행 예약액 `RUN_RESERVE_USD`, 전체 승인 총액 `APPROVED_TOTAL_USD`와 DB의 개인 예산 행까지 준비해야 합니다. 현재 비용 정산·결과 반영이 끝나지 않아 모든 값을 넣어도 실제 유료 호출은 코드에서 차단됩니다. 이 항목들을 활성화 대상으로 간주하지 마세요.

Preview는 Vercel Deployment Protection 등 실제 접근 제어를 확인하고 공유합니다. `noindex`는 검색 제외 요청일 뿐 접근 제어가 아닙니다. 운영 도메인·운영 DB·운영 환경변수는 변경하지 않습니다.

## 두 창에서 동시에 수정한 경우

다른 창의 저장본과 겹치면 자동 저장을 멈추고 현재 초안을 별도로 보관합니다. 설정 → ‘보관한 초안 확인’에서 문구를 비교하거나 ‘초안 백업 받기’로 파일을 받을 수 있습니다. 초안은 기존 프로젝트를 자동으로 덮어쓰지 않습니다. 필요한 문구를 복사한 다음 최신 저장본을 열어 반영해 주세요. 저장 공간 자체가 부족한 경우 보관이 실패할 수 있으므로 안내가 나오면 ‘저장 전 내용 백업 받기’를 먼저 이용하세요.

브라우저 검수 기록: `docs/review-checklist.md`. GitHub Actions 실행의 `review-evidence` 압축 파일에는 실제 테스트 화면이 있으며 보관 기간은 7일입니다. 예시 제품은 모두 허구이며 실제 업무 품질 승인 자료가 아닙니다.
