## 개인정보·제공 권한 사전 점검

추가 발췌에는 작성자명·IP·연락처·사진·건강 상세를 넣지 않았다. 개발 담당 AI의 예비 점검일 뿐이며 URL로 원 게시자에 연결될 가능성, 원문 범위·맥락과 이용 근거의 사용자 확인이 남는다. 원본 12개와 추가 9개 모두 앱 가져오기 권한/비식별 검토는 false 유지한다. 비식별 예비 점검을 외부 제공 권한으로 승격하지 않았다.

현재 실행 차단 사유는 (1) 선택 행별 외부 제공 근거/범위와 허용 서비스가 미확정, (2) 연결된 범용 외부 텍스트 분석 실행 도구 없음이다. 무료 또는 기존 구독 서비스도 임의로 선택하거나 로그인 세션을 탐색하지 않았다. 유료 API는 호출하지 않았다.

외부 실행에 필요한 결정은 선택 발췌 ID 범위, 사용 권한 근거와 비식별 검토, 서비스·모델, 사용자가 직접 실행해 원본을 전달할지 또는 지정한 서비스의 허용 경로를 사용할지다. 유료 API를 선택하면 서비스·모델·최대 입력/출력·3회 비용 상한과 데이터 범위를 최신 공식 요금에 따라 별도로 제출하고 승인 전 호출하지 않는다. 이 문서의 준비 묶음을 승인된 전송 묶음으로 표시하지 않는다.

## 정순·역순·해시 순서 비교 절차

1. 사용자 검토가 끝난 **동일한 프로젝트의 동일한 선택 행과 스냅샷**을 고정한다. 각 조건에서 미승인/제외 행이 생기면 비교 세트를 다시 동결하고 차이를 기록한다. 행 ID를 새로 만들지 않는다.
2. UI의 정순·역순·hash_order로 각각 별도 실행을 만든다. 모델·버전·설정은 같게, 각 실행은 새 대화로 독립 수행한다. 이전 응답·개발 지침·아래 감리표·사전 질문을 제공하지 않는다. 미공개 모델 버전·온도·seed는 미상으로 표시한다.
3. 앱의 해시 순서는 evidenceDigest(row UUID) 오름차순이다. 준비 manifest의 B/S 고정 ID 순서는 검토용 예시이며 실제 실행 순서가 아니다. 실제 run의 ordered row IDs·text SHA·snapshot/source digest·input/inputHash·prompt/promptHash·provider/model/version·시각을 보관한다. 정렬 규칙을 응답을 보고 바꾸지 않는다.
4. 응답 원본은 편집하지 않고 저장한다. 빈 응답·거절·중단·JSON/인용 위치/계약 오류도 실패 시도로 보존한다. JSON을 사람이 수선한 파일은 actual 모델 원본과 분리하며 원본 품질 실패를 지우지 않는다. 재실행은 새 기록으로 남긴다.
5. 모델 후보를 모두 합친 union 목록과 **전 입력 행별** 처리 목록을 대조한다. B01/B02/B04/B05/B06/S01/S05/S09의 직접 질문·조언 요청을 별도 확인하되, 각 행에서 몇 개 후보가 나와야 한다는 정답 수는 주입하지 않는다. B02/S09는 같은 사건이다.
6. 재구성·가설을 별도 채점하고 질문 문장의 어휘 일치만으로 군집 동일성을 판정하지 않는다. 지지 원문, 요청 과업·조건이 같은지 검토한다. 다른 제품·조건의 상충을 하나의 사실로 합치지 않는다.
7. 세 실행만으로 통계적 안정성을 입증하지 않는다. 결과는 이 표본·이 모델·이 설정의 관찰이며 재현 범위와 편차를 남긴다.

### 질문 후보별 제출 표와 누락 장부

현재 아래 표는 **미실행 상태표**이며 결과표의 빈칸을 모델 결과처럼 채우지 않는다. 실제 실행 후 발견 후보 전부를 한 행씩 기록하고 별도 누락 장부를 작성한다.

| 순서 조건 | 실행/모델·원본 | 질문 후보별 인용·AI 해석·대안 해석·검토자 판단 | 누락·오발견 | 상태 |
|---|---|---|---|---|
| 정순 | 없음 | 후보 없음 — 응답 미확보 | 미측정 | 권한·실행 경로 보류 |
| 역순 | 없음 | 후보 없음 — 응답 미확보 | 미측정 | 권한·실행 경로 보류 |
| 해시 순서 | 없음 | 후보 없음 — 응답 미확보 | 미측정 | 권한·실행 경로 보류 |

실제 후보 결과표 필수 열: run ID/후보 ref, 원문 행·URL·정확 인용/offset, 질문 문장·유형, AI의 상황/과업/장애/기대 결과와 basis, AI의 대안 해석, 검토자의 지지/과잉/오분류 판단·이유·검토자 신원, 대응 군집, 자동 gate 상태, 사람 승인 여부. 개발 AI 예비 검토와 사용자의 최종 의미 승인은 별도 열로 둔다.

누락 장부 필수 열: 모든 입력 row ID, 원문 직접 질문/요청 구간, 각 실행 disposition/후보 연결, 누락 여부·이유·분류 불확실성. 질문이 아닌 경험에서 억지 질문을 생성한 경우 오발견 장부에 기록한다. 발췌 자체에서 누락된 맥락은 **수집 범위 손실**이며 모델에 주어지지 않은 내용을 모델 발견 누락으로 계산하지 않는다.

### 판정 축과 보류 조건

- 인용 일치와 의미 지지는 별도다. 정확 인용을 붙여도 원문에 없는 책상 용도·공간 부족·장시간 품질·건강 효과를 추가하면 의미 오류로 기록한다.
- 직접 질문을 재구성/가설로 바꾸거나 경험을 observed로 분류한 사례는 분류 오류로 기록한다. 정의가 모호한 사례는 불확실로 남긴다.
- 상황·장애·기대 결과는 quote/interpretation/unknown을 구분한다. 근거 없는 요소를 단정하면 과잉 해석이다. 만족을 미충족으로 확정하거나 타인/가족 경험을 본인 경험으로 바꾸면 보류한다.
- B08~B12/S06/S07의 만족 표현과 B03/S03/S08의 부정 경험을 함께 보되, 동일 모델·조건의 상충으로 확정하지 않는다. 표본 관계가 불명확하면 우열·대표성 보류다.
