## 원자료 보존과 분리 상태

승인된 영구 보관 위치가 없어 data/poc-consumers의 8개 파일과 기존 실제 자료 fixture 1개 파일은 삭제·이동하지 않았다. 보존 대기 파일은 새 시험에서 읽지 않는다. 별도 로컬 감사 장부에서 원본 ID·배열 위치·본문 범위·수집 장부 연결·본문 SHA-256을 기록했다. 파일 9/9의 바이트 해시와 발췌 21/21의 본문 해시를 다시 대조했다. 이 임시 감사 장부와 공개 Git 이력은 정본 보관소가 아니다. 승인되지 않은 외부 저장소 업로드는 없다.

따라서 시험 입력과 실행 출력의 분리는 구현했으나, 최신 Git 트리의 실제 자료 제거는 보류다. `npm run check:public`은 9개 보존 대기 파일 때문에 실패해야 정상이다. 현 상태를 그대로 원격 반영하면 새 CI는 첫 경계 단계에서 중단되고 시험·artifact 업로드가 진행되지 않는다.

신규 경계 시험 1개는 최초 병렬 실행에서 기본 5초 제한에 걸렸다. 여러 하위 Node 실행을 수행하는 해당 시험의 제한을 20초로 조정한 후 전체 147개가 통과했다. 검증 assertion을 삭제하지 않았다.

Chromium 및 headless shell 설치는 배포 파일 다운로드/ZIP 오류로 실패했다. WebKit 바이너리는 받았으나 의존성 라이브러리가 부족했다. 의존성 설치도 환경의 패키지 접근/잠금 문제로 실패했다. 브라우저 버전이나 잠금을 강제로 대체하지 않았다. 따라서 앱 assertion·화면·정상 저장/재열기를 이번 UI 실행에서 검증했다고 보고하지 않는다.

보존한 실제 원문의 긴 구간 및 이전 실제 fixture 문자열을 기준으로 새 시험·소스·문서·현재 로그·빌드 정적 출력·실패 trace 텍스트를 로컬 대조했다. 검출은 없었다. 이미지 OCR·모든 표현 변형 검출·권한 판단을 보장하지 않으며, 정상 실행 스크린샷의 시각 검수는 UI 실행 환경 복구 후 남아 있다.

## 미해결과 다음

1. 승인된 접근 제한 보관 위치·담당자·보관 정책을 확정하고 실제 파일 및 원문-권한-위험 대응 문서를 옮긴 뒤 수량·ID·해시·범위를 대조해야 한다. 승인 전 정리는 보류한다.
2. 두 브라우저가 실행 가능한 환경에서 동일 SHA의 전체 UI 28개와 정상 화면/산출물 검사를 다시 수행해야 한다. 그 전 회귀 검증 완료를 선언하지 않는다.
3. 현재 원격 파일·과거 커밋·PR 설명·기존 CI artifact/캐시·외부 복제본은 이번 로컬 변경으로 사라지지 않는다. 삭제·보관기간·역사 정리는 별도 승인 대상이다. Private 전환·이력 재작성·강제 push는 하지 않는다.
4. 원격 반영은 위 보관/검증 조건을 충족한 변경과 CI 범위를 다시 제시하고 별도 승인받는다. 기존 브랜치 push는 Vercel Preview를 자동 생성할 수 있으므로 push와 Preview 영향 승인을 함께 확인한다. 현재 새 CI는 미정리 원자료를 발견하면 실패하도록 되어 있다.
5. B안 실제 분석은 관리 주체·적법한 이용 근거·외부 처리 정책·허용 계정·보관 위치 및 실제 모델/환경 확인, 정확한 전송 ID·해시·비식별 범위 승인 후에만 가능하다. 기존 21행의 외부 제공은 미승인이다. 초기 3회 탐색과 추가 6회 반복을 구분하며 실제 모델 검수 전 PoC2 전체 완료는 보류한다.
